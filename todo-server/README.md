# TODO App — Server

REST API для застосунку керування завданнями з JWT-аутентифікацією.

## Стек

- **NestJS** (працює поверх Express)
- **Prisma ORM** + **PostgreSQL**
- **JWT** — токен зберігається в httpOnly cookie
- **class-validator** — валідація вхідних даних
- **bcrypt** — хешування паролів

## Запуск

Потрібні Node.js 24+, pnpm і PostgreSQL.

```bash
# 1. Встановити залежності
pnpm install

# 2. Створити .env і за потреби змінити значення
cp .env.example .env

# 3. Застосувати міграції та згенерувати Prisma Client
pnpm prisma migrate dev
pnpm prisma generate

# 4. Запустити в режимі розробки
pnpm start:dev
```

Сервер запуститься на `http://localhost:3001`.

### Змінні оточення

| Змінна           | Опис                                     | Приклад                                                  |
| ---------------- | ---------------------------------------- | -------------------------------------------------------- |
| `DATABASE_URL`   | Рядок підключення до PostgreSQL          | `postgresql://postgres:postgres@localhost:5432/todo`     |
| `JWT_SECRET`     | Секрет для підпису токенів               | `change-me`                                              |
| `JWT_EXPIRES_IN` | Час життя токена                         | `1d`                                                     |
| `CLIENT_URL`     | Адреса фронтенду (для CORS)              | `http://localhost:3000`                                  |
| `PORT`           | Порт сервера                             | `3001`                                                   |

## Аутентифікація

Після реєстрації або входу сервер встановлює httpOnly cookie `access_token`. Браузер надсилає її автоматично; на фронтенді запити мають іти з `credentials: 'include'`.

Для ручного тестування (Postman, curl) токен також приймається в заголовку `Authorization: Bearer <token>`.

## API

### Auth

| Метод  | Шлях             | Опис                         | Тіло                  |
| ------ | ---------------- | ---------------------------- | --------------------- |
| `POST` | `/auth/register` | Реєстрація, встановлює cookie | `{ email, password }` |
| `POST` | `/auth/login`    | Вхід, встановлює cookie       | `{ email, password }` |
| `POST` | `/auth/logout`   | Вихід, очищає cookie          | —                     |

Пароль: щонайменше 6 символів, одна велика літера та один спецсимвол.

### Users

| Метод | Шлях        | Опис                                       |
| ----- | ----------- | ------------------------------------------ |
| `GET` | `/users/me` | Поточний користувач: `{ id, email, createdAt }` |

### Tasks

Усі ендпоінти потребують аутентифікації та працюють лише із завданнями поточного користувача.

| Метод    | Шлях         | Опис                                   | Тіло                                |
| -------- | ------------ | -------------------------------------- | ----------------------------------- |
| `GET`    | `/tasks`     | Список завдань (новіші першими)        | —                                   |
| `GET`    | `/tasks/:id` | Одне завдання                          | —                                   |
| `POST`   | `/tasks`     | Створити завдання                      | `{ title, description?, status? }`  |
| `PATCH`  | `/tasks/:id` | Оновити завдання (часткове оновлення)  | `{ title?, description?, status? }` |
| `DELETE` | `/tasks/:id` | Видалити завдання                      | —                                   |

**Фільтрація за статусом:** `GET /tasks?status=IN_PROGRESS`

**Статуси:** `TODO` (todo), `IN_PROGRESS` (in progress), `DONE` (done). За замовчуванням — `TODO`.

### Коди відповідей

| Код   | Коли                                                         |
| ----- | ------------------------------------------------------------ |
| `400` | Невалідні дані або `:id` не є UUID                           |
| `401` | Немає токена, токен невалідний або прострочений              |
| `404` | Завдання не існує або належить іншому користувачу            |
| `409` | Користувач із таким email уже існує                          |
